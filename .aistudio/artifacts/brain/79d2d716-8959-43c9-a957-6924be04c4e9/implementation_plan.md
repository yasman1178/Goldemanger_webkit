# خطة التطوير: تخصيص نسبة الدمغة والضريبة، دمج الجرد، وإظهار مخزن القطعة في البيع

تتيح هذه التحديثات لأصحاب وموظفي محلات الذهب التحكم المرن بنسبة الدمغة والضريبة من إدارة الشركة وتطبيقها تلقائياً على كل عمليات البيع، وتوحيد شاشة الجرد في جدول متكامل يدعم النقل وطباعة الباركود مع طباعة كشف مفصل للفلتر المختار، وإظهار رقم المخزن بوضوح على كارت القطعة في الكاشير.

---

### قرارات المستخدم ومحاور التنفيذ المؤكدة

> [!IMPORTANT]
> تم تأكيد الاختيارات التالية خلال جلسة التوضيح المسبقة وسيتم اعتمادها مباشرة في التنفيذ:

- **التحكم في نسبة الدمغة والضريبة**: تحديد وحفظ نسبة الدمغة والضريبة الافتراضية (كنسبة مئوية مثل 1% أو 1.5% أو أي نسبة متغيرة) من شاشة «إدارة الشركة»، مع حفظها في التخزين الدائم واستدعائها تلقائياً في حسابات سلة البيع وفاتورة البيع والإيصال المطبوع.
- **طباعة الجرد المصفى**: كشف تفصيلي كامل يعكس الفلاتر النشطة (مثل المخزن المختار، السلاسل، الكليات/العقود، أو نطاق الوزن) شاملاً القطع، الأوزان، العيارات، وتوزيع المخازن ومعادل عيار 21.
- **رقم المخزن في كارت البيع**: إضافة شارة بارزة ومدمجة وأنيقة بجانب شارة العيار والوزن توضح رقم واسم المخزن لكل قطعة معروضة في شبكة المنتجات (POS).

---

## 1. النظرة العامة ومفهوم الميزات

1. **الدمغة والضريبة الديناميكية**:
   - نسبة الدمغة والضريبة في سوق الصاغة تتغير وتختلف باختلاف الفترات والقرارات التنظيمية ونوع المشغولات.
   - إضافة حقل إعدادات مخصص في قسم «بيانات المحل» بصفحة «إدارة الشركة» (`CompanyManagePage`) يتيح للمالك إدخال وتعديل نسبة الدمغة والضريبة (مثلاً 1.0% أو 1.25%).
   - إنشاء متجر مشترك / هوك (`useTaxStore` أو ربطه بـ `localStorage` و `keyValues` للشركة) لتغذية معادلات `cartLineMath` وحسابات السلة في `SalesPage` و `CurrentCart` و `SaleReceiptView` تلقائياً بدون ثوابت جامدة.

2. **توحيد شاشة الجرد وإلغاء الازدواجية**:
   - حالياً تحتوي شاشة الجرد على جدولين منفصلين (جدول كميات المنتجات بالأعلى، وجدول القطع المخزنية بالأسفل).
   - دمج الجدولين في جدول جرد واحد ذكي ومتكامل يعرض القطع بتفاصيلها الكاملة، ويحتوي مباشرة في عمود الإجراءات على زر النقل بين المخازن وزر طباعة باركود القطعة (`InventoryUnitActions`).
   - ربط زر «طباعة كشف الجرد» بالبيانات المصفاة حالياً (Filtered Products / Units) بدلاً من كامل المخزون الخام؛ فعند تصفية «مخزن 3» أو تصنيف «سلاسل وعقود» أو «دلايات»، تُطبع فقط هذه المجموعة مع إجمالياتها الدقيقة وتوزيعها.

3. **إظهار رقم المخزن في كارت القطعة بكاشير البيع (POS)**:
   - يحتاج البائع لمعرفة مكان وجود القطعة الفعلي فوراً عند اختيارها أو عرضها للزبون.
   - تدعيم كارت المنتج في `ProductGrid` بشارة أنيقة عالية التباين تحمل أيقونة المخزن، ورقم المخزن `#ID`، واسم المخزن، موضوعة بدقة بين شارات العيار والوزن، ومتوافقة تماماً مع شاشات التابلت 10 إنش.

## 2. تجربة المستخدم والتصميم البصري (Tablet-First & Apple Design System)

- **الهوية البصرية**:
  - الالتزام الصارم بـ `DESIGN.md` الموحد: خلفيات بيضاء نقية، حدود رفيعة ناعمة (`border-black/5` و `elevation-card`)، وأزرار لمس مريحة $\ge 44\text{px}$ (`touch-target`).
  - ألوان واضحة: أزرق تفاعلي موحد (`primary`), لمسات الذهب للعيارات (`amber-600`), وأرقام مالية وأوزان ثابتة العرض (`tabular-nums font-bold`).
- **شاشة إدارة الشركة**:
  - إضافة بطاقة إعدادات مالية وضريبية أنيقة في `StoreSection` تتضمن حقل «نسبة الدمغة والضريبة (%)» مع زر حفظ سريع وتنبيه نجاح فوري.
- **شاشة الجرد الموحدة**:
  - دمج شريط التصفية والبحث ونطاق الوزن وكروت المعادل 21 في واجهة علوية موحدة ومرتبة.
  - جدول جرد موحد ومتناسق يوضح: كود/رقم المخزن، اسم القطعة، الفئة والنوع، العيار، الوزن، موقع المخزن، وزر الإجراءات (نقل لمخزن آخر + طباعة باركود 35x10mm).
  - ديالوج طباعة الكشف (80mm و A4) يعرض عنوان التصفية الحالي بدقة (مثل: «كشف جرد: مخزن رقم 3 — سلاسل وعقود») مع الإجماليات المطابقة تماماً للشاشة.
- **كارت البيع في POS**:
  - شارة مخزن مصممة بدقة `bg-sky-50 text-sky-800 border-sky-200/80` بجوار العيار والوزن مع تقليص استهلاك المساحة للحفاظ على وضوح صورة وسعر القطعة.

## 3. القرارات التقنية والبدائل المدروسة

```
┌────────────────────────────────────────────────────────────────────────┐
│                        قرارات التصميم المعماري                         │
├────────────────────────────┬───────────────────────────────────────────┤
│ النقطة المعمارية           │ القرار المعتمد والسبب                      │
├────────────────────────────┼───────────────────────────────────────────┤
│ إدارة نسبة الضريبة        │ تخزين النسبة في Store Profile / Storage    │
│                            │ مع fallback آمن إلى 1% عند عدم الضبط.     │
├────────────────────────────┼───────────────────────────────────────────┤
│ توحيد شاشة الجرد           │ دمج الجدولين في قائمة واحدة تعرض القطع   │
│                            │ المخزنية المتاحة وتضم إجراءات النقل       │
│                            │ والطباعة مع الحفاظ على سرعة التصفية.       │
├────────────────────────────┼───────────────────────────────────────────┤
│ طباعة الكشف المصفى         │ تمرير البيانات المصفاة (filtered items)    │
│                            │ إلى `InventoryReceiptPrint` لطباعة ما يراه │
│                            │ المستخدم فقط وليس كامل المخزون عشوائياً.   │
├────────────────────────────┼───────────────────────────────────────────┤
│ كارت البيع                 │ إبراز رقم المخزن مباشرة من `storageId`     │
│                            │ مع مطابقة الاسم من قائمة `storages`.      │
└────────────────────────────┴───────────────────────────────────────────┘
```

## 5. خطوات التنفيذ والتحقق

1. **إعدادات الدمغة والضريبة**:
   - إضافة حالة وإدارة نسبة الدمغة والضريبة في `src/shared/stores/tax-store.ts` أو `gold.ts` وتوفير هوك/دالة قراءة وتحديث سريعة.
   - تضمين حقل تعديل النسبة في `CompanyManagePage.tsx` ضمن بيانات المحل مع زر الحفظ وملاحظة توضيحية.
   - تحديث `cartLineMath` في `src/shared/lib/gold.ts` و `SalesPage.tsx` و `CurrentCart.tsx` و `SaleReceiptView.tsx` لاستخدام النسبة المضبوطة ديناميكياً.
2. **شاشة البيع وكروت المنتجات**:
   - تعديل `ProductGrid.tsx` لعرض شارة رقم واسم المخزن داخل كارت القطعة بأناقة عالية.
3. **توحيد شاشة الجرد وطباعة الكشف المصفى**:
   - إزالة الانفصال بين الجدولين في `InventoryPage.tsx` واعتماد جدول رئيسي موحد يضم بيانات القطع المخزنية المتاحة وإجراءات النقل والباركود.
   - تعديل `InventoryReceiptPrint.tsx` ليعتمد على المنتجات المصفاة (`filteredProducts`) مع تضمين اسم الفئة أو المخزن المختار في عنوان الكشف.
4. **سير التحقق الإلزامي**:
   - فحص الأنواع عبر `npm run typecheck`
   - فحص الكود عبر `npm run lint`
   - تشغيل الاختبارات عبر `npm run test`
   - بناء التطبيق بنجاح عبر `compile_applet`
